User Story 1
As a System Administrator, I want to configure the daily base rates for each Level of Care (LOC) tier, so that the billing engine can accurately calculate resident invoicing.
Acceptance Criteria 1:
Given the System Administrator is on the LOC Rate Table configuration screen
When they attempt to input a new rate value for any LOC tier (Tier 1 to Tier 5)
Then the system must validate that the input is a positive numeric value, greater than zero, and supports up to two decimal places.
Acceptance Criteria 2:
Given the System Administrator has modified the LOC rates
When they click the "Save Changes" button
Then the system must audit-log the change (User ID, Timestamp, Old Value, New Value) and display a success toast message: "LOC Rates updated successfully."
Acceptance Criteria 3:
Given the System Administrator leaves a required LOC field blank or inputs an invalid format
When they click "Save Changes"
Then the system must prevent submission, highlight the invalid fields in red, and display an error message: "Please enter a valid rate greater than $0.00."
User Story 2
As a System Administrator, I want to review the historical change logs of LOC tiers, so that I can audit rate fluctuations over time.
Acceptance Criteria:
Given the user is viewing the LOC Rate screen
When they click on the "View History" link for a specific tier
Then the system must display a read-only table containing Effective Date, Expiration Date, Rate, and the Administrator's name who authorized the change.
User Story 3
As a System Administrator, I want to set an effective start date for newly updated rates, so that future price adjustments apply automatically on the specified date.
Acceptance Criteria:
Given the Administrator is updating an LOC rate
When they select a future "Effective Date",
Then the system must keep the current rate active until midnight of the day before the new effective date, then seamlessly switch to the updated rate.
